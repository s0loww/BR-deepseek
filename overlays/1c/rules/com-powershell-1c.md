# 1C COM + PowerShell

Загружать это правило перед написанием или запуском скриптов, которые
подключаются к 1С через `V83.COMConnector`, читают/пишут документы,
справочники, регистры или вызывают методы базы через COM.

Generic-контракт таких скриптов (DryRun/Apply, exit-коды, отчёты, креды,
идемпотентность) — `rules/script-contract.md`. Правило ниже — стековая
надстройка над ним: что именно ломается в связке COM + PowerShell и как это
обходить.

## 1. Runtime

- По умолчанию — Windows PowerShell 5.1 (`powershell.exe`), **не** `pwsh`:
  `V83.COMConnector` в pwsh падает на `Connect()` (процесс умирает без внятной
  ошибки). Если pwsh уронил подключение — не диагностировать бизнес-логику,
  сразу переключиться на 5.1.
- Запуск строго через `-File`:

  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File <script.ps1> -Apply
  ```

  Вариант `-Command "& '...' -Apply ..."` нестабилен: стабильно умирает с
  ненулевым кодом после первой строки вывода, симптом обманчиво похож на краш
  COM-подключения. Тот же скрипт через `-File` отрабатывает сразу.
- Скрипты с кириллицей сохранять в **UTF-8 with BOM**: без BOM 5.1 читает файл
  как ANSI, кириллические литералы превращаются в мусор и парсер падает каскадом
  `Missing ')'` / `Unexpected token` на первой же кириллице — ошибка указывает
  на синтаксис, а причина в кодировке. Инструменты записи агента пишут UTF-8
  **без** BOM, поэтому сгенерированный скрипт пересохранять до запуска
  (`io.open(path, 'w', encoding='utf-8-sig')`); `pwsh` всеяден и такой ошибки не
  даёт.
- **`powershell.exe` может начать тихо умирать**: мгновенный exit 1, ноль байт
  вывода даже с полным редиректом, обрыв до первой строки скрипта — при том, что
  тот же скрипт под `pwsh` отрабатывает. Замечено после длинной сессии с
  массовыми файловыми операциями. Требование «строго 5.1» касается **только
  COM-подключений**: скрипты без COM (деплой, сборка, отчёты) в этом состоянии
  гонять через `pwsh`.
- Преамбула в начале скрипта:

  ```powershell
  $ErrorActionPreference = 'Stop'
  $OutputEncoding = [System.Text.Encoding]::UTF8
  [Console]::OutputEncoding = [System.Text.Encoding]::UTF8
  ```

## 2. COM-обёртки

Нельзя возвращать COM-результат из helper-функции обычным pipeline-возвратом,
если результат может быть коллекцией / табличной частью: PowerShell разворачивает
коллекции, и вместо COM-таблицы наружу выходит массив строк/значений (счётчики
ломаются). Обязательный паттерн — `InvokeMember` + `Write-Output -NoEnumerate`:

```powershell
function Invoke-ComMethod {
    param($Object, [string]$Name, [object[]]$Arguments = @())

    $result = $Object.GetType().InvokeMember(
        $Name,
        [System.Reflection.BindingFlags]::InvokeMethod,
        $null,
        $Object,
        $Arguments
    )
    Write-Output -NoEnumerate $result
}

function Get-ComPropertySafe {
    param($Object, [string]$Name)

    try {
        $result = $Object.GetType().InvokeMember(
            $Name,
            [System.Reflection.BindingFlags]::GetProperty,
            $null,
            $Object,
            @()
        )
        Write-Output -NoEnumerate $result
    } catch {
        return $null
    }
}
```

Для процедур без результата — отдельный wrapper или явное глушение в месте
вызова:

```powershell
Invoke-ComMethod -Object $documentObject -Name 'Записать' | Out-Null
```

Готовые обёртки — в `tools/com-tools/` (`OneC-Com.ps1`).

## 3. Коллекции

Коллекции 1С через COM выглядят по-разному — helper должен пробовать все
варианты по цепочке:

- количество: метод `Количество()`, метод `Count()`, свойство `Count`, либо уже
  развёрнутый PowerShell-массив (`.Length`);
- элемент: `Получить(index)`, затем `Get(index)`, для массива — `$Collection[$Index]`.

## 4. Документы

- Объект документа получать через `ПолучитьОбъект()` (`Invoke-ComMethod -Object
  $reference -Name 'ПолучитьОбъект'`).
- Документ, который просят просто поправить, записывать обычной `Записать()` и
  **не** проводить / не отменять проведение без отдельного требования. Запись без
  проведения — режим по умолчанию.
- Системные enum режима записи (`РежимЗаписиДокумента.*`, `DocumentWriteMode.*`)
  через COM ненадёжны: могут вернуться как `$null` или дать несоответствие типов.
  Перед массовым применением — прогнать на **одном** документе и перечитать флаг
  `Проведен`. Числовые значения enum безопасной заменой не считать: база может не
  принять их как нужный COM-тип.
- Номера документов **периодические** → искать всегда по паре `Номер + Дата`, не
  по одному номеру.

## 5. Запросы

- Ссылки в выборке выводить через `ПРЕДСТАВЛЕНИЕ(...)`, а не как PowerShell-строку
  от COM-объекта — иначе в отчёте будет `System.__ComObject`.
- Сравнение с перечислением делать в тексте запроса через
  `ЗНАЧЕНИЕ(Перечисление.<Имя>.<Значение>)`, а не COM-доступом к менеджеру
  перечисления.
- Даты задавать **полным интервалом дня**: `...T00:00:00` … `...T23:59:59`.
  Передача только `ГГГГ-ММ-ДД` означает полночь и может дать 0 документов.
- Параметры выносить в `.sql`-файл с заголовками `; @param Имя=значение`
  (`@date:` / `@number:` / `@bool:`). Если параметр вроде `&Номенклатура` ведёт
  себя странно — проверить минимальный вариант (короткое имя параметра) тем же
  текстом запроса.
- В превью тяжёлых запросов добавлять `ВЫБРАТЬ ПЕРВЫЕ N`.
- Раннер превью падает `Object reference not set` на NULL из `ЛЕВОЕ СОЕДИНЕНИЕ`
  и на несуществующих полях. Правило для запросов раннера: без `ЛЕВОЕ
  СОЕДИНЕНИЕ`, потенциально пустые ссылки — только через `ПРЕДСТАВЛЕНИЕ()`
  (пустая ссылка даёт `""`, это безопасно).

## 6. Безопасность записи / удаления

Общий контракт мутирующего скрипта — `rules/script-contract.md`: DryRun по
умолчанию и мутации только под явным `-Apply`, честные коды возврата,
машиночитаемый отчёт в лог-каталог, перечитывание реального состояния после
применения, идемпотентность. Здесь — только то, что добавляет COM.

- Удаление дубля справочника — только через полный цикл: найти нормальную
  карточку → заменить документные ссылки на неё → записать документы обычной
  `Записать()` → сохранить CSV-лог замен → и только потом `Удалить()`.
- `НайтиПоСсылкам()` даёт список владельцев ссылок, но не гарантирует конкретное
  поле/строку (возвращает массивы, где `[0]` — искомая ссылка, `[1]` —
  объект-владелец, `[2]` — объект метаданных владельца, `[3]` часто `null`).
  Конкретные места замены подтверждать запросами к табличным частям и менять
  целево.

## 7. Профиль подключения

Откуда берутся секреты и почему их не бывает в аргументах и логах —
`rules/script-contract.md`. COM добавляет форму профиля:

- Профили подключения — в git-ignored `.env`, секции `[<Профиль>]`:
  `Mode` (`File`/`Server`/`Auto`), `Path` (для File) либо `Host`+`Ref` (для
  Server), `Login`, `Pass`.
- Путь к `.env` и имя профиля — **обязательные параметры** скрипта, без дефолтов
  и хардкода: подключение к боевой базе не должно получаться по умолчанию.
- Маскируется именно строка подключения целиком, а не только пароль:
  `File="...";Usr="user";Pwd="***";` — путь к базе в логе тоже лишний.

## 8. Жизненный цикл

- Работа с базой — под `try/finally`.
- Освобождение COM в `finally`: обнулить ссылки, затем
  `[System.GC]::Collect()` и `[System.GC]::WaitForPendingFinalizers()`.

## 9. Грабли и проверенные обходы

- **`GetType()` падает** на некоторых объектах 1С (например, наборах записей
  регистра): конфликт двуязычных имён (`Записать`/`Write`) при построении
  .NET-обёртки — `Item has already been added. Key: 'WRITE'`. На таком объекте
  не работают ни `Invoke-ComMethod`, ни `Get-ComPropertySafe` (оба зовут
  `GetType()`). `[System.__ComObject].InvokeMember` напрямую кириллические члены
  тоже не резолвит. Обход — скриптовый хост (`cscript`), см. следующий пункт.
- **Обход через `cscript` — брать JScript, не VBScript.** Файл в UTF-16 LE,
  запуск `cscript //Nologo`. Членов платформы касаться английскими синонимами
  (`NewObject("Query")`, `.Text`, `.Execute().Select()`, `.Next()`,
  `.GetObject()`, `.Write`, `.Filter.Find(...)`), поля выборки алиасить
  латиницей (`КАК Ref`). Но у имён, заданных **метаданными** — измерения,
  ресурсы, реквизиты — английского синонима не существует, и обратиться к ним
  можно только по строке. JScript это умеет скобочной нотацией:

  ```js
  var filter = recordSet.Filter.Find('Физлицо');  // синоним платформы
  record['Физлицо'] = person;                     // имя из метаданных
  ```

  **VBScript для этого не годится:** кириллические идентификаторы в нём
  запрещены, а `CallByName` в VBScript отсутствует — он есть только в VB6/VBA.
  Обращение к члену по строке взять неоткуда, и обход упирается в тупик на
  первом же измерении регистра. Проверено на записи набора записей
  `РегистрСведений` с кириллическими измерениями.

  Креды передавать через переменные окружения процесса, не в командной строке.
  Коды возврата разводить явно (записано / исключение при записи / сбой запуска),
  чтобы вызывающий PowerShell отличал их без разбора текста.
- **Файловая база**: подряд идущие COM-сессии могут мгновенно ронять
  `powershell.exe` (вывод обрывается до «Подключено») — держать паузу
  30–60 с между сессиями и делать один ретрай.
- **XML-сериализация типов расширений через внешнее соединение не работает**:
  `ВозможностьЧтенияXML()` возвращает `Ложь`, а `ПрочитатьXML()` —
  `Неопределено` для объектов, чьи метаданные добавлены расширением, хотя
  запросы и менеджеры тех же объектов через то же соединение отвечают штатно.
  Не чинится ни маршалингом, ни JScript-обходом — это ограничение XDTO-фабрики
  соединения. Обход: разбирать XML самому (MSXML / `XmlDocument`) и создавать
  объекты через менеджер — `CreateItem()`, `SetNewObjectRef(GetRef(UUID))` для
  сохранения исходных ссылок, `DataExchange.Load = true` перед `Write()`.
- **Публикация базы на веб-сервере держит файловую ИБ.** После обращений к
  опубликованному HTTP-сервису соединение живёт ещё минуты: конфигуратор не
  получает монопольный доступ и деплой падает. Перед деплоем после HTTP-прогонов
  — перезапуск веб-сервера или пауза до таймаута сеанса. Обратное тоже верно:
  первый HTTP-вызов после деплоя может упасть по оборванному соединению —
  один ретрай.
- **Долгий COM-вызов «молчит» до возврата**: вывод серверной функции виден
  целиком только по завершении вызова — прогресс наблюдать по CPU процесса
  (`Get-Process`), а не по логу. Массовые `СтрЗаменить` по строкам в сотни МБ
  внутри 1С идут минутами (строки неизменяемые, каждая замена копирует строку
  целиком) — тяжёлую текстовую предобработку выносить за пределы 1С.
- **Кириллица в теле HTTP-запроса из `curl` под Git Bash бьётся**: `curl -d '...'`
  конвертирует тело в ANSI, база получает мусор, а симптом обманчиво похож на
  проблему кодировки на стороне 1С. Тестировать HTTP-сервисы телом из файла,
  записанного в UTF-8: `curl.exe --data-binary "@file.json"`.
- **Открытый клиент со старой версией расширения** после динамического
  обновления конфигурации ломает последующие COM-подключения — закрыть
  клиентские сеансы перед прогоном.

## 10. Перед написанием нового скрипта

- Готовая библиотека — `tools/com-tools/`: сначала смотреть туда,

  запросов.
- Generic-контракт скриптов — `rules/script-contract.md`.
