# Правила обмена в КД 2.0

Правила живут **в справочниках самой ИБ КД**, а не в файлах проекта. Результат
работы — XML, который грузится в «Универсальный обмен данными в формате XML» в
конфигурации-источнике.

**Транспорт вне этого правила.** Ниже — BSL, который надо выполнить *в* ИБ КД, и
запросы к её справочникам. Каким каналом ты туда попадаешь (MCP-сервер, COM,
внешняя обработка, руками в конфигураторе) — определяет раздел `1C tooling`
корневого контракта `AGENTS.md` (конкретные вызовы — `tooling-playbooks.md`).
Правило описывает, **что** выполнять и почему именно так.

Работать на **тестовой копии** ИБ КД: правила пишутся прямо в справочники.

**Конкретика контура — не сюда.** Имена конвертаций и объектов вашего обмена,
пути к файлам правил, маппинг перечислений между конкретной парой конфигураций —
проектный слой: спецификация задачи и документация проекта.
Здесь остаётся то, что одинаково у всех, кто пишет правила в КД.

## 1. Объектная модель

```
Конфигурации              (описывает источник или приёмник)
  └─ Объекты              (Владелец=Конфигурации) — объекты метаданных
       └─ Свойства        (Владелец=Объекты) — реквизиты объекта
            └─ Значения   (Владелец=Свойства) — значения перечислений

Конвертации               (пара «источник → приёмник»)
  ├─ ПКО                  (Владелец=Конвертации, Родитель=ПКО-группа)
  │   ├─ ПКС              (Владелец=ПКО)
  │   └─ ПКЗ              (Владелец=ПКО)
  ├─ ПВД, ПОД             (Владелец=Конвертации)
  └─ Алгоритмы, Запросы, Параметры

Регистрации
  └─ ПРО                  (Владелец=Регистрации)
```

| Сокр. | Что это |
|---|---|
| ПКО | правило конвертации объекта |
| ПКС | правило конвертации свойства (реквизита) |
| ПКГС | группа свойств — ПКС с `ЭтоГруппа = Истина` |
| ПКЗ | правило конвертации значения перечисления |
| ПВД / ПОД | правила выгрузки / очистки данных |
| ПРО | правило регистрации объекта к обмену |

Справочники иерархические («папки и элементы», 2 уровня); папки —
логическая группировка правил внутри одной Конвертации.

**Владелец — главная связь.** Она же определяет порядок создания: без ссылки на
Владельца элемент писать бессмысленно.

## 2. Три вещи, которые ломают программное создание правил

### 2.1 `Код` у ПКО/ПКС/ПКЗ вручную не задавать

Модуль объекта проверяет имя правила на корректность, и GUID (с дефисами, с
цифры) корректным именем **не является** — запись отклоняется с «Не правильно
указано имя правила!». Оставлять `Код` пустым: платформа сгенерирует его из
имени объекта-приёмника (`ПоступлениеНаРасчетныйСчет00001`) и сделает
уникальным.

У **Конвертации** наоборот: `Код` = GUID (строка 40 символов) — норма.

Признак этой ошибки коварен: `Записать()` падает с общим «Не удалось
записать…», а `ПолучитьСообщенияПользователю()` возвращает **ноль** сообщений —
КД пишет не в общий стек. Почти всегда причина одна из двух: некорректный `Код`
или пустой `Приемник`.

### 2.2 ПКС создаётся по **ссылкам**, а не по текстовым именам

Самая частая ошибка. Если задать только `ИмяИсточника`/`ИмяПриемника`
строками, КД в `ПередЗаписью` **сбросит их в пустую строку**, не найдя свойства
с таким именем в справочнике `Свойства`. ПКС сохранится мусором, в выгрузке
даст параметр без имени, а загрузчик в приёмнике упадёт с «Поле объекта не
обнаружено».

```bsl
// Свойство ищется подчинённым объекту: Владелец — ЧЕТВЁРТЫЙ параметр,
// третий (Родитель) пропускается.
СвПриемник = Справочники.Свойства.НайтиПоНаименованию("Доп_НомерАСУФХД", Истина, , ПКО.Приемник);
Если СвПриемник.Пустая() Тогда
    // Свойства нет в теневой модели — сначала загрузить структуру метаданных
    ВызватьИсключение "Свойство не найдено в метаданных КД";
КонецЕсли;

ПКС = Справочники.ПравилаКонвертацииСвойств.СоздатьЭлемент();
ПКС.Владелец = ПКО;
ПКС.Приемник = СвПриемник;          // ИмяПриемника подтянется само
ПКС.Порядок  = 1000;
ПКС.Записать();
```

После записи проверять `ПКС.ИмяПриемника`: пусто — значит свойство не нашлось и
правило записалось мусором.

Задавать вручную нужно только `Источник`, `Приемник`, `ПравилоКонвертации` (для
ссылочных) и `Родитель` — остальное (`ИмяИсточника`, `ТипИсточника`,
`ВидИсточника`, `Наименование`, `Порядок`) модуль заполнит из ссылок сам.

### 2.3 `НайтиПоНаименованию` в подчинённом справочнике — с Владельцем

Без Владельца поиск вернёт **произвольный** подходящий элемент, в том числе из
чужой Конвертации, и правило молча привяжется не туда. Сигнатура:
`НайтиПоНаименованию(Наименование, ТочноеСоответствие, Родитель, Владелец)` —
Владелец **четвёртый**, третий пропускается.

Искать ПКО по `Коду` не стоит: `Код` — строка фиксированной длины с хвостовыми
пробелами (§10), и `НайтиПоКоду("Контрагенты")` не найдёт ничего.

### 2.4 ПКС табличной части — через `СоздатьГруппу()`

`ЭтоГруппа` — системное поле, присвоить его нельзя («Поле объекта недоступно
для записи»). Для ПКС табличной части — `СоздатьГруппу()`, для обычного
реквизита — `СоздатьЭлемент()`. Дочерние ПКС реквизитов табчасти получают
`Родитель = <ПКС-группа>`.

## 3. Имена в теневой модели — с префиксом типа

В справочнике `Объекты` поле `Наименование` хранит **полное** имя типа:
`ДокументСсылка.ПоступлениеНаРасчетныйСчет`, `СправочникСсылка.Контрагенты`,
`ПеречислениеСсылка.ВидыОпераций`. Короткое имя — в поле `Имя`.
`НайтиПоНаименованию` искать по полному, иначе вернётся пусто. То же для
`ТипИсточника`/`ТипПриемника` в ПКО.

**Иерархия значений у перечисления короче на уровень.** У документа и
справочника: `Значения → Свойства → Объекты`. У перечисления значения подчинены
объекту-перечислению **напрямую**: `Значения.Владелец = Объекты`. Обращение
`Знач.Владелец.Владелец.Владелец` для перечисления упадёт с «Поле не найдено».

## 4. Перечисления: ПКО-перечисление + ПКЗ

Трансформация значения перечисления делается парой:

- **ПКО-перечисление**: `Источник`/`Приемник` — объекты-перечисления обеих
  конфигураций;
- **ПКЗ** (Владелец = это ПКО): `Источник`/`Приемник` — ссылки на `Значения`,
  `ЗначениеИсточник`/`ЗначениеПриемник` — строковые имена значений.

ПКС реквизита-перечисления в документе обязан ссылаться на это ПКО через
`ПравилоКонвертации` — иначе значение не сконвертируется.

Если перечисления в обеих конфигурациях **тождественны**, ПКЗ строится
поле-в-поле по совпадению имён; если различаются — маппинг N→1 руками.

### Когда ПКО-перечисление и ПКЗ не нужны вовсе

Если у источника такого перечисления нет или соответствие вычисляется
алгоритмом — достаточно положить в переменную `Значение` в
`АлгоритмПередВыгрузкойСвойства` **строку с именем значения приёмного
перечисления**. На загрузке КД сама найдёт значение с таким именем в
перечислении, заданном типом реквизита-приёмника. `ПравилоКонвертации` в этой
ПКС оставлять пустым.

```bsl
// Источник — объект исходной ИБ, перечислений приёмника здесь нет
ИмяВида = "";
Для Каждого МетаЗн Из Метаданные.Перечисления.ВидыОперацийПоступление.ЗначенияПеречисления Цикл
    Если Перечисления.ВидыОперацийПоступление[МетаЗн.Имя] = Источник.ВидОперации Тогда
        ИмяВида = МетаЗн.Имя;
        Прервать;
    КонецЕсли;
КонецЦикла;
Значение = ИмяВида;   // просто строка — приёмник подставит своё значение по имени
```

Полноценные ПКО-перечисление и ПКЗ нужны тогда, когда имена принципиально не
совпадают и требуется явный маппинг N→M.

## 5. Поиск объекта в приёмнике — где теряются ссылки

Классический симптом: документ загрузился, а его ссылочные реквизиты —
«Объект не найден», хотя поля поиска в ПКО справочника заданы.

Порядком поиска управляют **два** реквизита ПКО, и поиск по внутреннему
идентификатору перебивает поля поиска:

| `СинхронизироватьПоИдентификатору` | `ПродолжитьПоиск…ЕслиПоИдентификаторуНеНашли` | Поведение |
|---|---|---|
| Ложь | неважно | только поля поиска — бизнес-ключ работает |
| Истина | Ложь | только внутренний GUID; не нашёл — стоп |
| Истина | Истина | GUID, при неудаче — переход на поля поиска |

Внутренние GUID в источнике и приёмнике **разные**, когда НСИ ведётся
независимо и не наполняется этим обменом. Отсюда и «объект не найден» при
корректно заданных полях поиска.

Правится в самом проекте КД, реквизитом ПКО:

```bsl
Объект = ПКО.Ссылка.ПолучитьОбъект();
Объект.ПродолжитьПоискПоПолямПоискаЕслиПоИдентификаторуНеНашли = Истина;
Объект.Записать();
```

Правка того же флага **в выгруженном XML или в макете слетит** при следующей
выгрузке правил.

**Поиск НСИ по ГУИД.** ПКС по реквизиту-ГУИД с `Поиск = Истина`; само ПКО при
этом обычно `НеЗамещать`, `НеВыгружатьОбъектыСвойствПоСсылкам` и
`НеСоздаватьОбъектВПриемникеЕслиНеНайденПоПолямПоиска`. В выгруженном XML
атрибут английский — `<Свойство Поиск="true">`; поиск по слову «Истина» в XML
ничего не найдёт.

## 6. Движения регистров передаются опционально

Два режима, и от выбора зависит, что писать в обработчиках:

- **движения включены в ПКО** (ПКС-группы по регистрам движений рядом с ПКС
  реквизитов) — приёмник получает готовые движения, перепроводить документ не
  нужно;
- **движения не включены** — документ загружается с
  `Объект.ОбменДанными.Загрузка = Истина` (запись без проведения) и **после**
  загрузки проводится механизмом обмена; движения формирует
  `ОбработкаПроведения` приёмника по своим счетам и виду операции.

Во втором режиме счета в приёмник не переносятся и руками не заполняются — их
определит проведение по виду операции. Поэтому трансформация вида операции
через ПКЗ становится критичной: ошиблись в ней — получите неверные проводки при
формально успешной загрузке.

## 7. Обработчики: `Объект` — это `ДокументОбъект`, а не структура

В `АлгоритмПослеЗагрузкиОбъекта` и соседних переменная `Объект` — платформенный
`ДокументОбъект` приёмника, строки табчастей — `ДокументТабличнаяЧастьСтрока`.
Метода **`.Свойство()` у них нет**: он есть только у `Структура`,
`Соответствие` и `ДанныеФормыСтруктура`. Привычная защитная проверка падает с
«Метод объекта не обнаружен (Свойство)»:

```bsl
// Упадёт на обмене
Если СтрокаТЧ.Свойство("СпособПогашения") И СтрокаТЧ.СпособПогашения.Пустая() Тогда

// Реквизит известен из метаданных — проверять наличие незачем
Если СтрокаТЧ.СпособПогашения.Пустая() Тогда
```

Если состав реквизитов различается по типам документов — разделять логику по
типу, а не проверять наличие. Там, где защита действительно нужна, —
`Попытка/Исключение` вокруг присваивания.

Из этого же следует правило выбора типовых методов: **метод с пометкой «для
контекстных вызовов из формы» в обмене не работает** — внутри он идёт в
`ПараметрыЗаполнения.ДанныеФормы.Объект.Свойство(...)`. Нужен парный
внеформенный метод, принимающий объект напрямую. Для счетов учёта БП это
`СчетаУчетаВДокументах.Заполнить(Объект, Отбор)`, а не
`ЗаполнитьОбъектПриИзменении`:

```bsl
Отбор = Новый Структура("НеЗаполненныеРеквизиты", Истина);
СчетаУчетаВДокументах.Заполнить(Объект, Отбор);
```

## 8. ПВД — точки входа выгрузки

Без ПВД выгружаемый объект не «стартует»: ПКО описывает, *как* конвертировать,
а ПВД — *что* выбирать. Создавать ПВД для документов; справочникам НСИ они не
нужны — те тянутся по ссылкам.

Реквизиты (Владелец = Конвертации): `ОбъектВыборки` (= `ПКО.Источник`),
`ПравилоКонвертации` (ссылка на ПКО), `СпособОтбораДанных` =
`СтандартнаяВыборка`. Остальное — `ТипОбъектаВыборки`, `ИмяПравилаКонвертации`,
`Код`, `Наименование` — заполнит `ПередЗаписью`.

В XML ПВД лежат в `<ПравилаВыгрузкиДанных>` тегом `<Правило>` — **тем же**, что
и ПКО. Считая правила парсером, учитывать оба блока, иначе получите завышенное
число ПКО.

## 9. Удаление и дубли: правила не выкидываются просто так

- `Удалить()` **зависает** на модальном подтверждении связанных объектов —
  не использовать.
- `УстановитьПометкуУдаления(Истина)` отрабатывает, но помеченные правила
  **всё равно попадают в выгрузку**.
- Реквизит `Отключить` — тоже **не** исключает ПКС из XML.
- Пометка удаления и `Отключить` подряд дают «Операция не может быть выполнена,
  так как данные объекта модифицированы»: после правки реквизита нужен
  `Записать()`, и только потом отдельный вызов пометки.
- Сменить `Владелец` у ПКО на другую конвертацию платформа не даёт.

Практика: лишнее правило либо физически удалять через UI КД («Все функции» →
«Удаление помеченных объектов») **до** выгрузки, либо вырезать блок
`<Правило>…</Правило>` из готового XML текстом — файл остаётся well-formed.
Мусорную ПКС, которую удалить нельзя, хотя бы очистить от алгоритмов, чтобы она
не тащила код в XML.

## 10. Итоговый XML

Порядок групп в корне `<ПравилаОбмена>` фиксирован: `ПравилаКонвертацииОбъектов`,
`ПравилаВыгрузкиДанных`, `ПравилаОчистки`, `Алгоритмы`, `Запросы`.

Имена в XML **не совпадают** с именами реквизитов справочника: реквизит
`ПравилаОчисткиДанных` в XML — `<ПравилаОчистки>`,
`НеСоздаватьОбъектВПриемникеЕслиНеНайденПоПолямПоиска` — `<НеСоздаватьЕслиНеНайден>`.
Сверяться с фактическим маппингом, а не с именем реквизита.

`Код` — строка фиксированной длины, в XML приезжает с хвостовыми пробелами:

```xml
<КодПравилаКонвертации>Контрагенты                    </КодПравилаКонвертации>
```

При сравнении — `СокрЛП()`.

## 11. Выгрузка правил

```bsl
Обр = Обработки.ВыгрузкаКонвертации.Создать();
Обр.КонвертацияДляВыгрузки         = Справочники.Конвертации.НайтиПоНаименованию("<имя>");
Обр.ИмяФайлаПравил                 = "{EXPORT_PATH}/rules.xml";
Обр.СжиматьФайлПравил              = Ложь;
Обр.ВыгружатьПравилаКорреспондента = Ложь;
Обр.ВыгружатьПравилаРегистрации    = Ложь;
Обр.ВыполнитьВыгрузкуПравил();
```

`ИмяФайлаПравил` должен указывать на **существующий** каталог;
`КаталогВременныхФайлов()` — надёжный вариант.

Выгрузка **комплекта** (`ВыгружатьПравилаКорреспондента` и/или
`ВыгружатьПравилаРегистрации` = Истина, три файла в ZIP для обмена БСП)
обращается к прогрессору шире, чем простая выгрузка одной конвертации. При
программном запуске форма не создаётся, поэтому заглушку ставить сразу со
всеми четырьмя полями:

```bsl
Обр.мФормаПрогрессора = Новый Структура(
    "Значение,КомментарийЗначения,МаксимальноеЗначение,КомментарийОбработкиДанных",
    0, "", 0, "");
```

Простая выгрузка одной конвертации без заглушки отрабатывает штатно.
`Состояние("…")` без интерфейса просто игнорируется, падения не будет.

## 12. Массовые изменения

**Отмены последнего действия в КД нет.** Перед пакетной правкой — копия файловой
ИБ или выгрузка текущих правил как бэкап.

Создание сотни ПКС в цикле — **в одной транзакции**: без неё каждая запись
открывает свою, и на реальных конвертациях (100+ ПКС в одном ПКО) это заметно.

```bsl
НачатьТранзакцию();
Попытка
    Для Каждого Поле Из Поля Цикл
        // ... создание и Записать()
    КонецЦикла;
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ВызватьИсключение;
КонецПопытки;
```

Часть системных операций требует `УстановитьПривилегированныйРежим(Истина)`.
Сама выгрузка XML быстрая: 100+ ПКО и 800+ ПКС — единицы секунд.

## 13. Запросы к справочникам КД

В тексте запроса не работают BSL-функции (`ПустаяСтрока`, `СтрСоединить`,
`СтрРазделить`) — для пустой строки сравнение `Поле <> ""`. Индексатор по
строке (`Объект["Реквизит"]`) есть у Структуры и Соответствия, но **не** у
`СправочникОбъект` — только через точку.
